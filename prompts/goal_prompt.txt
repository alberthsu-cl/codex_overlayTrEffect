/goal

Build and refine one new transition shader from this sample video:

Sample video:
D:\PATH\TO\YOUR\NEW_SAMPLE.mp4

Sample ID (lowercase only - must match [a-z0-9][a-z0-9_-]*, so an uppercase
or space-separated ID is rejected at step 1):
your_new_sample_id

Work only under:
D:\AI_Harness\agent\work\samples\your_new_sample_id

Goal:
Create one new ModelGenerated FX ID, establish a valid calibrated baseline, then
run at most three candidate refinement evaluations for that same FX ID.

Process:

1. Initialize the sample workspace with the given sample ID and video.

2. Prepare 60 reference frames at 1920x1080 and generate reference motion
   diagnostics.

3. Analyze the sample directly using:
   - agent/prompts/agent_transition_analysis_prompt.md
   - agent/prompts/agent_transition_analysis_schema.json
   - prepared reference frames and reference motion diagnostics

   Save the valid transition_structure JSON under the sample analysis folder.

4. Prepare source A/B using the default endpoint mode:
   - source A is original video frame 0
   - source B is the final decoded video frame
   - do not require manual frame indices or source-boundary analysis

5. Sync the effect catalog. Analyze the design using:
   - agent/prompts/effect_design_prompt.md
   - agent/prompts/effect_design_schema.json
   - the transition analysis
   - current registered OverlayTrEngine effects

   Delivery policy: this sample must produce a new shader deliverable. Assign a
   unique ModelGenerated\Family_XX FX ID, and choose the starting point
   explicitly between the two available actions:

   - implement_new_effect starts from the neutral scaffold, ModelGenerated/
     TrGeneratedDissolve: a plain linear crossfade with a wrapper that passes
     progress through unmodified, carrying no inherited geometry or timing.
   - tune_existing_effect clones a registered effect, builtin or generated, as
     a starting point only; never modify the effect it clones. Prefer this only
     when a registered effect already implements most of the required motion,
     and say in decision.reason what it actually supplies.

   A cloned seed carries its timing as well as its pixel logic. Before relying
   on one, check that its UpdatePSParam passes progress through linearly - some
   effects remap it to a narrow band around the transition midpoint, which makes
   the shader look broken for most of its progress range. The scaffold is the
   safe default when in doubt.

6. Build the render job. Generate the effect seed, register it, and initialize
   its isolated candidate workspace. Derive the effect folder name from
   target_effect.effect_id; do not invent a second FX ID.

7. Run the initial candidate evaluation with:
   - reference transition output window from transition_structure.json
   - --calibrate-progress
   - a unique backup directory

   Confirm the endpoint checks meet baseline tolerance. If they do not, fix
   the workflow/configuration issue before starting refinement.

8. Configure the candidate evaluation profile using only actual resolved paths,
   never literal documentation placeholders. Start a shader_refinement phase
   with max-iterations 3 and max-rejected 3. Generate the first request with
   --evaluate-after-edit.
   Do not stop after phase initialization; immediately follow the generated
   first iteration request.

9. For up to three refinement iterations:
   - read and follow the newest iteration_NNN_agent_request.md;
   - edit only that candidate workspace;
   - run its embedded candidate-evaluate command;
   - after an accepted, rejected, or tradeoff outcome, run candidate-continue;
   - use the next generated request.
   `candidate-continue` is mandatory after every completed evaluation unless
   the phase is exhausted, blocked, or a build/evaluation failure requires the
   generated repair request.

   Pinned-schedule rule: refine against a fixed progress schedule, not a
   recalibrated one. --calibrate-progress re-probes the candidate on every run
   to find the frames distinct from both endpoints, then maps the reference
   window onto that band. Any change to an effect's temporal profile - a longer
   tail, a slower relaxation, an earlier onset - moves what the probe finds and
   silently re-times the content, so the score then reports content
   misalignment rather than the change that was made. One measured instance:
   extending a stretch tail moved the probe's band end from 0.85 to 0.98 and
   the iteration read as a regression for that reason alone.

   Once the step 7 baseline is accepted, pin it:
   - read reports/progress_calibration.json from the baseline run and copy the
     aligned_evaluation_job.json it names to a stable path under the sample's
     jobs/ folder, and shorten its job_name field - that name is embedded in
     every evaluation output path, and Windows still caps paths at 260
     characters, which a generated job_name has already exceeded;
   - run every refinement evaluation with --job pointing at that pinned file
     and WITHOUT --calibrate-progress;
   - confirm the pin is faithful by re-evaluating the unchanged baseline under
     it once; the metrics must reproduce the baseline's. If they do not, the
     pin is wrong - fix it before spending an iteration.

   Re-derive a measurement only against the pinned schedule. A curve fitted
   under one mapping is invalid under another.

   Motion-first rule: when reliable motion coverage is high but direction
   agreement is weak, investigate regions or displacement before blur or
   blend. Keep the approach general; do not assume a fixed number of regions
   or a horizontal-only transition.

Stop when three refinement evaluations have completed, the controller reaches a
budget/block/failure state, or a required build/evaluation fails. Report the
final FX ID, selected baseline iteration, final report path, and comparison
video path.
