/goal

Build and refine one new transition shader from multiple sample videos of the
same effect: one primary and one or more secondary videos. The example below
shows 3 secondaries (A, B, C); add or remove secondary entries for however
many you actually have (1, 2, 4, 5, ...) - every step that touches "each
secondary sample" repeats once per secondary, whatever that count is. Nothing
in this template is tied to a specific number of secondaries.

Primary sample video:
D:\PATH\TO\YOUR\PRIMARY_SAMPLE.mp4

Primary sample ID:
YOUR_EFFECT_NAME

Secondary sample videos (one line per secondary; add/remove lines to match your count):
D:\PATH\TO\YOUR\PRIMARY_SAMPLE_DESCRIPTOR_A.mp4
D:\PATH\TO\YOUR\PRIMARY_SAMPLE_DESCRIPTOR_B.mp4
D:\PATH\TO\YOUR\PRIMARY_SAMPLE_DESCRIPTOR_C.mp4

Secondary sample IDs (must start with the primary sample ID; one line per secondary, same order as above):
YOUR_EFFECT_NAME_DESCRIPTOR_A
YOUR_EFFECT_NAME_DESCRIPTOR_B
YOUR_EFFECT_NAME_DESCRIPTOR_C

Work only under (one folder per sample video - primary plus every secondary):
D:\AI_Harness\agent\work\samples\YOUR_EFFECT_NAME
D:\AI_Harness\agent\work\samples\YOUR_EFFECT_NAME_DESCRIPTOR_A
D:\AI_Harness\agent\work\samples\YOUR_EFFECT_NAME_DESCRIPTOR_B
D:\AI_Harness\agent\work\samples\YOUR_EFFECT_NAME_DESCRIPTOR_C

Goal:
Create one new ModelGenerated FX ID from the primary sample, establish a valid
calibrated baseline, run at most three candidate refinement evaluations for
that same FX ID, then run a one-time advisory regression check against every
secondary sample.

Process:

1. Initialize every sample workspace (the primary and each secondary) with
   its given sample ID and video.

2. For every sample (the primary and each secondary): prepare 60 reference
   frames at 1920x1080 and generate reference motion diagnostics.

3. For every sample (the primary and each secondary), analyze it directly
   using:
   - agent/prompts/agent_transition_analysis_prompt.md
   - agent/prompts/agent_transition_analysis_schema.json
   - that sample's own prepared reference frames and reference motion
     diagnostics

   Save each valid transition_structure JSON under that sample's own analysis
   folder. Do not mix sources or diagnostics between samples.

4. Run reconcile-analyses across every sample's transition_structure.json
   (the primary plus every secondary) and write the result to the primary
   sample's analysis folder. The command accepts any number of --analysis
   files - list one per sample, not just three:

   ```powershell
   conda run -n harness python agent/src/main.py reconcile-analyses `
     --analysis "agent\work\samples\YOUR_EFFECT_NAME\analysis\transition_structure.json" `
                "agent\work\samples\YOUR_EFFECT_NAME_DESCRIPTOR_A\analysis\transition_structure.json" `
                "agent\work\samples\YOUR_EFFECT_NAME_DESCRIPTOR_B\analysis\transition_structure.json" `
                "agent\work\samples\YOUR_EFFECT_NAME_DESCRIPTOR_C\analysis\transition_structure.json" `
     --output "agent\work\samples\YOUR_EFFECT_NAME\analysis\cross_sample_consensus.json"
   ```

   From here on, only the primary sample is built, registered, and refined.
   No secondary sample is rendered or registered against directly until the
   final step.

5. Prepare source A/B for the primary sample only, using the default endpoint
   mode:
   - source A is the primary's original video frame 0
   - source B is the primary's final decoded video frame
   - do not require manual frame indices or source-boundary analysis

6. Sync the effect catalog. Analyze the design using:
   - agent/prompts/effect_design_prompt.md
   - agent/prompts/effect_design_schema.json
   - the primary sample's transition analysis
   - the cross_sample_consensus.json from step 4
   - current registered OverlayTrEngine effects

   Treat fields the consensus marks convergent (agreed across every sample)
   as trustworthy structural primitives, safe to encode directly in the
   shader. Treat fields it marks divergent (sample-specific, or supported by
   only some samples) as approximate; keep them procedural/parametric rather
   than tuned to the primary sample's own specifics. A field's support count
   (e.g. "3 of 4 samples") is a confidence signal, not a majority vote - a
   field only one sample disagrees on can still be the correct one; verify
   ambiguous cases against the actual reference video rather than trusting
   the count alone.

   Delivery policy: this sample must produce a new shader deliverable. Assign
   a unique ModelGenerated\Family_XX FX ID. Existing effects may be cloned
   only as a starting point; do not modify them.

7. Build the render job from the primary sample. Generate the effect seed,
   register it, and initialize its isolated candidate workspace. Derive the
   effect folder name from target_effect.effect_id; do not invent a second FX
   ID.

8. Run the initial candidate evaluation against the primary sample with:
   - reference transition output window from the primary's transition_structure.json
   - --calibrate-progress
   - a unique backup directory

   Confirm the endpoint checks meet baseline tolerance. If they do not, fix
   the workflow/configuration issue before starting refinement.

9. Configure the candidate evaluation profile using only actual resolved
   paths, never literal documentation placeholders. Start a shader_refinement
   phase with max-iterations 3 and max-rejected 3. Generate the first request
   with --evaluate-after-edit.
   Do not stop after phase initialization; immediately follow the generated
   first iteration request.

10. For up to three refinement iterations, against the primary sample only:
    - read and follow the newest iteration_NNN_agent_request.md;
    - edit only that candidate workspace;
    - run its embedded candidate-evaluate command;
    - after an accepted, rejected, or tradeoff outcome, run candidate-continue;
    - use the next generated request.
    `candidate-continue` is mandatory after every completed evaluation unless
    the phase is exhausted, blocked, or a build/evaluation failure requires
    the generated repair request.

    Motion-first rule: when reliable motion coverage is high but direction
    agreement is weak, investigate regions or displacement before blur or
    blend. Keep the approach general; do not assume a fixed number of regions
    or a horizontal-only transition.

Stop when three refinement evaluations have completed and every secondary
sample's regression check has run, the controller reaches a
budget/block/failure state, or a required build/evaluation fails. Report the
final FX ID, selected baseline iteration, final report path, comparison video
path, and each secondary sample's regression check result.
